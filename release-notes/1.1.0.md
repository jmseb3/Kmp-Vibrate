# KMP Vibrate 1.1.0

## Highlights

- Added configurable vibration strength to the shared API.
- Added built-in feedback presets for common UI interactions.
- Improved API safety with support checks and shared timing validation.
- Expanded the sample app with platform-specific Android, iOS, JS, and Wasm JS demos.
- Refreshed the README with 1.1.0 installation coordinates and updated usage examples.

## What's Changed

### Configurable Strength

`VibratorManager` now supports a normalized `strength` value from `0f` to `1f`.

```kotlin
VibratorManager.vibrate(300, strength = 0.5f)
VibratorManager.vibrate(VibrationPreset.Success, strength = 0.8f)
```

- Android maps strength to vibration amplitude on API 26+.
- iOS maps strength to Core Haptics intensity.
- JS and Wasm JS keep API compatibility and ignore strength because the browser Vibration API does not support amplitude.

### Built-in Presets

`VibrationPreset` now includes reusable feedback patterns:

- `Click`
- `DoubleClick`
- `Tick`
- `Success`
- `Warning`
- `Error`
- `Heartbeat`
- `Sos`

Each preset exposes its pattern data and total duration:

```kotlin
val timings = VibrationPreset.Success.timings
val duration = VibrationPreset.Success.durationMillis
```

### Safer Pattern Handling

Shared validation now rejects invalid vibration requests before they reach platform implementations:

- non-positive one-shot durations
- empty or odd-sized timing lists
- negative timings
- zero-length vibration windows
- invalid strength values such as `NaN`

### Sample App Updates

The sample project now demonstrates:

- one-shot vibration
- custom delay/vibrate patterns
- preset patterns
- support checks through `VibratorManager.isSupported()`
- platform-specific sample modules for Android, iOS, JS, and Wasm JS

## Installation

```kotlin

    implementation("io.github.jmseb3:vibrate:1.1.0")
}
```
